## v0.3.2：确认后自动替换与重启（2026-11-02）

启动检查发现新版即展示模态更新弹窗，更新说明直接显示，仅保留“立即更新 / 稍后”。API 失败的发行页面备用检查会提取 body-content 内的说明文本。确认后在当前 EXE 同目录创建独立临时目录，下载并校验，无文件选择器和完成弹窗。

下载成功后隐藏启动更新辅助进程；辅助进程验证新旧文件哈希并报告就绪后，主窗口走原有停止领取、退出回调和断开连接流程。辅助进程等待旧进程完全结束，再通过 Windows File.Replace 原子替换当前 EXE 并保留短暂回退副本。启动新版后，主窗口显示并验证自身哈希后确认启动，辅助进程才删除旧 EXE 和临时文件。失败则回退并启动旧版，设置和日志不移动。路径、参数以 JSON 与独立进程参数传递，支持中文、空格和单引号；无递归清理用户目录。

Windows 原生回归使用实际占用中的 EXE，覆盖等待退出、替换、启动、删除旧文件、启动失败恢复、保留设置，以及损坏文件拒绝安装。74 项 Python 与 15 项 JavaScript 检查通过。tools/verify_self_update.py 已用真实 dist/BP.exe 在隔离目录完成替换、打开 v0.3.2 主窗口、旧文件与临时目录清理和原设置保留验证。实际 GitHub 页面备用检查成功提取 v0.3.1 的 613 字更新说明。

## v0.3.1：内置更新与应用图标（2026-11-02）

Windows EXE 与窗口标题使用简称 BP（Beast Pick），输出为 dist/BP.exe，发行 ZIP 为 BP-v版本号-windows-x64.zip。仓库、Python 模块、实例锁、设置与日志路径保持原命名。v0.2.x 更新资产按旧文件名 beast-pick.exe 识别，v0.3 系列使用 BP.exe，API 检查、下载和 SHA-256 校验均使用对应版本的文件名。正式发布版本为 v0.3.1，之前交付的 v0.3.0 为本地测试构建。

启动后后台查询 GitHub 最新正式发行版本，也可手动检查。版本按数字比较，忽略草稿及预发行；接口失败时回退到同一仓库的 latest 发行页面重定向。后台只提示可用更新，下载必须经用户选择并指定保存路径。

更新请求由独立的 Qt 异步网络管理器处理，不占用游戏连接工作线程。下载先取得同版本 SHA256SUMS.txt，再流式写入 QSaveFile；同时限制下载大小、核对完整长度（接口提供时）并验证 SHA-256。只有校验通过才原子保存目标，取消、超时或校验失败丢弃临时文件，保留已有文件。拒绝覆盖正在运行的 EXE，不自动运行下载文件。完成后用户退出并替换原 EXE，保留 settings.json。

补给箱与拾取箭头 PNG 使用内置 ImageGen 生成，保留透明背景；ICO 为 16、24、32、48、64、128、256 像素七种尺寸。图标应用于 EXE、窗口和任务栏，源文件与生成提示见 beast_pick/assets/README.txt。打包检查逐帧核对 PE 中的图标资源与源 ICO。

离线覆盖版本比较、正式发行与下载地址验证、API 限流回退、用户选择稍后/下载、下载成功、取消、HTTP 错误、截断、超长、校验失败和关闭窗口取消请求。67 项 Python 与 15 项 JavaScript 检查通过，包括新旧 EXE 名称的版本检查、下载与校验；实际打包 EXE 自检、GitHub 版本检查和 PE 图标逐帧核对通过。生产更新模块的真实联网检查已通过当前 v0.2.1 的发现、下载（108880497 字节）与 SHA-256 校验，不执行下载文件。

## 实现

Python 3.12 / PySide6 提供界面、热键、连接管理和日志；Frida 17.24.0 在游戏进程中运行一个小型 JavaScript 代理。代理调用引擎空间查询取得周围真实物体，按类型与状态筛选，使用游戏原有领取路径。

固定适配 EXE 显示为 1.7.1.0na 的当前安装构建。连接时对实际加载的引擎 DLL、游戏 DLL 做 SHA-256 和映像大小校验，错误构建不安装运行钩子。哈希、偏移和入口在 `beast_pick/profiles/current.json`。Frida 17.25.0 在本机附加失败，故固定使用 17.24.0。

## 原生调用

- `ILevel::FindObjectsInRadius` 返回 IControlObject；通过运行时类型识别 BodyContainer、Container、ComplexContainer、DroppedItem、ContainerItem。
- 当前构建 IGame 虚表 151、152、153 用于角色变换、玩家实体列表、本地玩家实体；由本地实体取得实际玩家对象。
- 所有游戏查询和领取统一在 `IGame::GetGameTimeDelta` 的指定模拟更新调用点运行（引擎 RVA 0xBC3D22），不从 Python 工作线程直接调用领取函数。
- BodyContainer：检查启用标记、状态 1、非空物品向量；调用已观察到的初始化与 ILootable 领取入口。返回成功且物品向量减少才计数。
- DroppedItem / ContainerItem：复用本地玩家当前交互上下文，先调用正常可使用判定，再调用领取；清除交换标记，不使用 G 换装。下一次范围查询确认目标消失后才计数。
- Container：只处理状态 1/2、启用标记正常且 full+0x570 没有附属脚本触发器的对象。虚表 196/197 必须匹配 0x1121810/0x1194280；状态 2 先正常 can-use/execute action 7，下一轮重新查询。状态 1 先正常 can-use action 1，再调用该类 init 0x118B190 与共用 ILootable 逐项领取，不强写状态。使用与尸体相同的 CategoryType 过滤和向量减少确认。
- ComplexContainer：仅状态 2 且散落物品功能已启用时尝试打开；虚表 196/197 必须匹配 0x1121730/0x1193F50。正常 can-use/execute action 7 后确认状态 1，仅记为打开；下一轮查询生成的 ContainerItem，按现有筛选领取并确认消失。不把“打开”计为内容已经领取，不缓存子物品指针，不执行开锁动作。

## 持续运行

默认半径 8 米，按用户反馈扩展为可调 1–500 米，仅能查询到游戏已加载的目标。每 0.3 秒重新查询（扫描耗时上升时自动放缓，最大间隔 1.5 秒），每轮至多处理 3 个目标。不会保存下一轮需要执行的原生指针。失败按 2、4、8、16、30 秒退避；搜空的尸体不再领取。远距离领取尚需结合实际场景验证。

暂停、加载、失去前台、本地玩家未就绪、玩家实体数不为 1 时等候。新场景需稳定后才查询。Python 心跳超过 5 秒没有更新即关闭功能。关闭窗口卸载钩子并断开。
